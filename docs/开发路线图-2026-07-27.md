# 我密码呢开发路线图

- 建立日期：2026-07-27
- 原则：先保证数据不丢失和可恢复，再提高日常录入效率，最后扩展交换格式和跨端能力。

## 阶段一：数据可靠性

### 第 1 步：未保存内容保护

- 状态：已完成（2026-07-27）
- 范围：分区、账号清单、分类、标签编辑器，以及程序窗口关闭。
- 验收：内容发生变化后关闭窗口，必须提供“保存修改、放弃修改、继续编辑”；没有变化时直接关闭。
- 实现：四类编辑器统一使用未保存确认窗口；存在草稿时注册程序窗口关闭提醒，多账号清单以初始快照作为变化判断基准。
- 验证：分区、多账号清单、分类、标签的继续编辑、放弃修改和保存入口均已通过浏览器实测；8 项单元测试和生产构建通过。

### 第 2 步：安全导入与回滚

- 状态：已完成（2026-07-27）
- 导入前展示数据版本、分区、账号、图片数量和备份时间。
- 替换当前数据前自动创建加密回滚备份。
- 导入验证或保存失败时保持原数据不变，并提供回滚路径。
- 实现：加密备份先解锁再预览；JSON 与加密备份统一执行版本、主清单、编号和引用完整性校验；确认后先生成 `rollback-before-import-*.anb`，再执行原子数据替换。
- 数据保护：回滚备份失败时不启动写入；SQLite 写入失败时保留旧记录；导入图片写入唯一新文件，失败时不会覆盖旧图片；日志失败不再反向判定数据导入失败。
- 验证：导入预览、取消、成功替换、回滚路径和无效未来版本均已通过浏览器实测；18 项前端测试、6 项 Rust 测试和生产构建通过。

### 第 3 步：日志与标签规则

- 状态：已完成（2026-07-27）
- 日志明确记录密码变化、历史密码选择、标签变化和图片增删，但不写入敏感正文。
- 标签禁止空名称和重复名称；删除被引用标签时显示引用数并确认。
- 实现：账号日志按字段记录密码设置、更新、清除、历史密码复用、旧密码保留选择、图片增删数量及其他变更字段；不记录密码、备注、密保答案、图片名称、网址或数据正文。
- 标签规则：名称自动去除首尾空格，空名称或忽略大小写后重名时禁止保存；标签管理显示分区引用数，删除被引用标签前二次确认并同步解除引用。
- 验证：空名称、重名、引用数和删除确认均已通过浏览器实测；密码更新与保留、历史密码复用、图片增加和标签增删日志均已验收，日志中未出现测试密码或图片信息；23 项前端测试、6 项 Rust 测试、Rust 格式检查和生产构建通过。

## 阶段二：日常效率

### 第 4 步：安全设置完善

- 状态：已完成（2026-07-27）
- 支持重新生成恢复码并立即废止旧恢复码。
- 设置页显示最近备份时间、数据大小和图片占用。
- 实现：恢复码轮换仅重新包装当前数据密钥，不重新加密整库；安全配置通过同目录临时文件同步落盘后原子替换，成功后旧恢复码无法再解锁当前软件。
- 交互：重新生成前显示废止影响并二次确认；新恢复码仅显示一次，未勾选“已另行保存”时不允许关闭设置。旧加密备份仍使用创建时的启动密码或恢复码。
- 数据统计：数据页显示最近 `.anb` 备份时间与数量、整个 `data` 目录占用和 `images` 目录占用，并可手动刷新。
- 验证：恢复码生成、轮换、旧码失效、新码解锁和恢复码登录后强制改密提示已通过浏览器实测；数据页在 1280 及 1000×700 视口下无遮挡；24 项前端测试、9 项 Rust 测试、Rust 格式检查和生产构建通过。

### 第 5 步：默认密码模板

- 状态：已完成（2026-07-27）
- 数据：应用数据升级至 v3，在完整加密备份中保存一个全局固定密码模板；v1/v2 数据自动补齐空设置。
- 设置：使用 `{网站名称}` 占位符配置固定结构，实时预览生成结果、长度及大小写英文、数字、特殊符号和占位符识别状态；缺少占位符时禁止保存，清空模板即可关闭功能。
- 账号：仅在模板已配置时显示“使用模板”，默认取当前分区名称并在弹窗中预览；已有密码必须明确确认覆盖，填入动作只修改账号草稿。
- 兼容：账号最终保存继续使用原有密码更新确认及最近 3 条历史密码规则；修改日志只记录模板已更新或已清除，不记录模板正文。
- 验证：旧版迁移、完整备份保留模板、模板解析及结构识别测试通过；浏览器实测模板保存、非法模板拦截、未保存关闭保护、空密码填入、已有密码覆盖确认、原密码历史确认及清空后隐藏入口；设置页和账号编辑器在 1280 及 1000×700 视口下无遮挡。

### 第 6 步：搜索定位

- 状态：已完成（2026-07-28）
- 搜索结果结构化区分分区、账号、备注、分类和标签命中，并在记录行显示命中字段与截断摘要。
- 搜索账号名称、登录账号、身份识别码、自定义字段或密保信息时，自动进入所属分区并选中首个匹配账号；密码正文不参与搜索。
- 搜索备注标题或内容时，自动选中对应账号并在结果中标记“备注”；点击结果可在用户手动切换账号后重新定位匹配账号。
- 保留原有分类层级和多标签组合筛选；搜索期间禁用记录拖拽排序，清空搜索后恢复完整列表并保留当前账号位置。
- 验证：31 项前端测试、生产构建、9 项 Rust 测试及 Rust 格式检查通过；浏览器实测分区名称、账号和备注三类定位，1000×700 与 1280×800 视口下无横向溢出，控制台无错误或警告。

## 阶段三：交换与扩展

### 第 7 步：Excel 与 Word

- 状态：已完成（2026-07-28）
- 数据交换入口集中提供加密备份/恢复、标准 Excel 导出/导入和只读 Word 导出；Office 导出前明确提示文件包含明文账号、密码、密保答案和历史密码。
- Excel 使用“说明、分类、标签、分区、账号、历史密码、密保问题、自定义字段、备注、图片”等可见工作表保存结构化字段；原始图标和账号图片以小于单元格上限的 Base64 分块保存在隐藏工作表中，ICO/WebP 等格式只转换 Office 预览，导回时恢复原始字节。
- Excel 仅接受带版本标记的本程序标准模板，解析和引用校验全部在内存中完成；确认后复用现有导入预览、导入前加密回滚和原子保存流程，失败时原数据不变。
- Word 按分区和账号生成查看/打印文档，包含文字、超链接、历史密码和行内图片；不提供 Word 导入或任意排版文档解析。
- 桌面版只允许将 `.xlsx`/`.docx` 写入便携数据目录下的 `exports`，浏览器开发模式使用下载；Office 代码按需加载，不影响日常启动路径。
- 验证：33 项前端测试、10 项 Rust 测试、生产构建通过；真实浏览器完成 Excel 下载、标准模板导入预览、安全回滚替换、图片恢复和 Word 下载，1000×700 窗口无遮挡且控制台无错误或警告。Excel 12 个工作表、关键范围和公式错误扫描已检查，可见工作表已完成渲染检查，并由本机 Excel 复核 3 个图片对象和空单元格。Word 结构审计确认 1 个 Letter 纵向节、1 英寸页边距、3 个行内图片和完整标题层级；当前机器缺少 LibreOffice，且 Word COM 导出超时，因此未完成 DOCX 逐页 PNG 视觉检查。
- 2026-07-30 回归：新增多分区、多账号、超长字段与横竖图片压力夹具；Word 图片按原始比例缩放，字段表格行禁止跨页拆分，长账号、密码、识别码、网址和备注允许词内换行。图片审计与 34 张表格几何审计通过，88 项前端测试、25 项 Rust 测试、生产构建和 Tauri release `--no-bundle` 构建通过。标准 LibreOffice 渲染器不可用且 Word COM 仍超时，因此逐页 PNG 视觉检查继续保留为环境受限项。

### 第 8 步：可选图片加密

- 状态：已完成（2026-07-28）
- 设置 > 安全提供独立开关，默认关闭；旧版数据迁移到 v4 时不会静默加密已有图片。
- 图片和图标沿用 vault 的 32 字节数据密钥，使用 AES-256-GCM 与随机 nonce 写入紧凑二进制容器；保留原扩展名和 `storedPath`，不改变备份、预览和 Office 往返关系。
- 开启或关闭时按原路径事务式迁移，临时文件写入并同步后通过 Windows `ReplaceFileW` 原子替换；替换失败时旧文件保持不变。中断留下的明文/密文混合状态会在下次加载时按设置修复，认证失败不会把密文当作图片。
- 单张图片仍受 15 MB 限制，迁移时明文与密文会短暂同时驻留，约需两倍原始字节内存；当前界面本身使用 Data URL，不增加重复缩略图缓存。大批量迁移由设置按钮显式触发，避免启动时无提示处理。
- 验证：34 项前端测试、14 项 Rust 测试、生产构建和 Tauri release 构建通过；PNG、JPG、WebP、GIF、BMP、ICO 原始字节往返、错误密钥、密文篡改、同路径迁移、去重复用、内容变化新文件及原子替换失败回滚均有测试覆盖。浏览器实测设置保存和未保存保护，1000×700 视口无遮挡且控制台无错误或警告。

### 第 9 步：同步与安卓前置数据模型

- 状态：已完成（2026-07-28）
- 数据：AppData 升级至 v5；分类、标签、分区、账号和设置均有独立 revision、更新时间和修改设备，旧数据自动迁移并固定 vault ID。
- 删除：分类、标签、分区和账号使用最小墓碑；分区级联删除会为分区和账号分别留痕，同一 ID 重建时延续墓碑 revision 后再清除墓碑。
- 本机：`data/device.json` 保存随机设备 ID、对应 vault 和最近成功同步游标，不进入完整备份且不含任何 vault 密钥或账号内容；提供原子更新成功游标的 Tauri 命令。
- 协议：快照升级为 `account-notebook-sync-v2`，包含快照 ID、父快照 ID、vault revision 和设备 ID；条件推送使用预期远端快照 ID，避免竞态覆盖。
- 冲突：本地和远端同时偏离共同基线、vault 不同、revision 回退、快照编号异常或远端基线消失时停止覆盖；记录级双方同时修改时不因 revision 数值相同而误判为一致。
- 交换：完整加密备份保留 lineage 与墓碑；Excel 继续作为人工交换格式，导回后建立新 lineage，不伪造同步历史。
- 验证：48 项前端测试、16 项 Rust 测试、Rust 格式检查和生产构建通过；浏览器实测新建分区、仅密码账号和设置页说明，1000×700 视口无遮挡且控制台无错误或警告。
- 边界：未接入网络同步提供方、后台服务、冲突处理界面或安卓工程；同步服务未来仍只允许传输加密快照。
