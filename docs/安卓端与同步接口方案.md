# 我密码呢安卓端与同步接口方案

- 状态：第 9 步前置数据模型已完成；网络服务、同步适配器和安卓应用未实现
- 更新日期：2026-07-28

## 1. 边界

同步服务只允许接触加密后的 vault 快照，不接触 `AppData` 明文、启动密码、恢复码、数据密钥或单独图片文件。桌面端与未来安卓端分别在本机完成解锁、加密和解密。

当前程序仍为纯本地应用，不增加后台常驻进程、网络账号或远程依赖。同步 DTO、规划器和禁用提供方位于 `src/lib/sync.ts`；本机设备身份由 Tauri 保存在 `data/device.json`。

## 2. AppData v5

分类、标签、分区和账号统一携带记录版本：

```ts
interface RecordVersion {
  revision: number;
  updatedAt: string;
  modifiedByDeviceId: string;
}
```

`AppData.sync` 保存同一份 vault 的共享元数据：

```ts
interface AppSyncMetadata {
  vaultId: string;
  revision: number;
  settingsRevision: number;
  settingsUpdatedAt: string;
  settingsModifiedByDeviceId: string;
  tombstones: DeletionTombstone[];
}
```

- 新建实体从 revision 1 开始，只有内容实际变化时才递增。
- 一次本地保存无论修改多少实体，只把 vault revision 递增一次；无变化保存不递增。
- 删除实体会生成墓碑；删除分区时，分区与其账号分别生成墓碑。
- 墓碑只保存实体类型、ID、revision、删除时间和设备 ID，不保存名称、密码或正文。
- 同一 ID 删除后重新建立时从墓碑 revision 继续递增，再清除旧墓碑，避免被其他设备的旧删除状态覆盖。
- v1-v4 数据首次加载后迁移到 v5，并立即保存稳定的 vault ID 和版本信息。

## 3. 本机设备与游标

`data/device.json` 只描述当前便携目录的设备身份和最近成功同步位置：

```ts
interface SyncLocalState {
  formatVersion: 1;
  deviceId: string;
  lastSyncedVaultId: string | null;
  lastSyncedSnapshotId: string | null;
  lastSyncedVaultRevision: number;
  lastSyncedAt: string | null;
}
```

设备 ID 为随机 `device-` 加 32 位十六进制字符，重复读取保持不变。`device.json` 不进入 `.anb` 完整备份，不保存密码、恢复码、数据密钥或账号内容。`record_sync_success` 只在未来同步流程确认推送或拉取成功后更新游标，并拒绝同一 vault 的 revision 回退。

## 4. 加密快照协议

同步载荷使用 `account-notebook-sync-v2`：

```ts
interface EncryptedVaultSnapshot {
  format: "account-notebook-sync-v2";
  vaultId: string;
  snapshotId: string;
  parentSnapshotId: string | null;
  vaultRevision: number;
  createdAt: string;
  deviceId: string;
  encryptedBackup: string;
}
```

`encryptedBackup` 复用桌面端 `.anb` 加密备份内容。提供方只负责状态查询、拉取和条件推送：

```ts
interface SyncProvider {
  getStatus(): Promise<SyncStatus>;
  pull(): Promise<EncryptedVaultSnapshot | null>;
  push(snapshot: EncryptedVaultSnapshot, expectedRemoteSnapshotId: string | null): Promise<void>;
}
```

`expectedRemoteSnapshotId` 是条件写入前置条件。远端头快照不匹配时必须拒绝推送，不能用“最后写入者覆盖”掩盖并发修改。

## 5. 冲突策略

`planSnapshotSync()` 使用本机游标、当前 vault revision 和远端头快照给出保守决策：

| 情况 | 决策 |
| --- | --- |
| 首次同步且远端为空 | 条件推送 |
| 本地未改、远端从基线前进 | 拉取 |
| 远端仍是基线、本地已改 | 以基线快照 ID 条件推送 |
| 双方都从共同基线修改 | 停止并报告冲突 |
| vault 不同、revision 回退、快照编号异常、远端基线消失 | 停止并报告冲突 |

`decideEntitySync()` 只提供记录级保守判断。单侧修改可选该侧；双方 revision 都前进时，即使数值相同也视为冲突，因为相同 revision 不能证明内容相同。当前不做逐字段自动合并，也没有冲突处理界面。

## 6. 备份与 Office 边界

- `.anb` 和完整 JSON 数据保留 vault ID、所有 revision 及墓碑，可延续同一 lineage。
- 导入 v5 完整备份时校验版本字段、墓碑唯一性、revision 上界以及墓碑与现存实体互斥；失败时沿用安全导入机制，原数据保持不变。
- Excel 是人工编辑交换格式，不携带同步游标或删除历史；导回后建立新的 vault lineage，墓碑为空。
- `device.json` 始终属于本机，不随完整备份迁移。

## 7. 安卓端建议

建议使用 Kotlin、Jetpack Compose、Room 和 Android Keystore：

1. UI 和本地数据库按安卓平台独立实现，不直接复制桌面 SQLite 文件。
2. 复用 AppData v5 DTO、AES-256-GCM 信封、Argon2id 参数、密钥包装和快照 v2 契约。
3. 启动密码与恢复码语义和桌面端保持一致；解锁后的数据密钥只驻留进程内存。
4. Android Keystore 只用于可选的设备级便捷解锁，不能替代跨设备恢复规则。
5. 图片随加密 vault 迁移，落盘后仍按稳定 ID 关联账号。
